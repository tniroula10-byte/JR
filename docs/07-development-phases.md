# 07 — Development Phases (`docs/07-development-phases.md`)

Execution proceeds autonomously through Phases A and 0–11 in strict order. Every phase requires passing its self-check and recording evidence in `docs/PROGRESS.md` before advancing.

| Phase | Scope | Mandatory Self-Check |
| :--- | :--- | :--- |
| **Phase A** | Folders, `AGENTS.md`, planning docs (`01`–`08`), `PROGRESS.md`, `HUMAN-TODO.md`, `DECISIONS.md`, `runbook.md`, `security-checklist.md` | All files exist; docs agree with the brief. |
| **Phase 0** | Next.js App Router scaffold, TypeScript strict mode, Tailwind CSS + design tokens, shadcn primitives, linting, GitHub Actions CI workflows, data-adapter skeleton (`lib/data/`) | `npm run lint`, `npm run typecheck`, and `npm run build` pass; theme renders on mobile and desktop. |
| **Phase 1** | Full frontend on realistic mock data for all 3 roles (`customer`, `employee`, `boss`) across all screens in Section 10, including loading, empty, and error states | Every role's screens opened in the browser with screenshots saved under `docs/screenshots/`; no layout breaks at `360px`, `768px`, and `1280px`; accessibility score >= 90. |
| **Phase 2** | Supabase schema (`supabase/migrations`), enums, triggers, helpers, RLS & storage policies, `supabase/apply_all.sql`, magic-link auth, invite flow (boss & employee rules), boss bootstrap (`scripts/seed-boss.ts`), triple route guards, `supabase` data adapter | SQL / unit tests prove isolation for every role (including `suspended`); uninvited email cannot sign in; role cannot be escalated; employee cannot invite an employee. `supabase/apply_all.sql` generated and documented in `docs/HUMAN-TODO.md`. |
| **Phase 3** | User management (invite, suspend, permission flags, aliases), products CRUD and validated image upload | Automated tests prove `hidden` products are unreachable by customers even by direct repository/API call; permission flags enforced. |
| **Phase 4** | Chat: RPCs (`send_customer_message`, `send_staff_message`), `message_attribution`, realtime updates, unread counts, shared inbox, handler claim, notifications | Two browser contexts exchange messages live; customer payloads never contain staff identity; `employee_inbox_scope` (`all` vs `assigned_only`) verified both ways. |
| **Phase 5** | Offers: `submit_offer`, structured chat offer cards, staff negotiation actions (`counter`, `accept`, `reject`, `withdraw`), handler tracking | Atomic creation verified; forged offer messages rejected; invalid/negative/over-cap amounts rejected. |
| **Phase 6** | Tickets: creation, optional selectable employee alias, assignment, status machine (`transition_ticket`), ticket threads, read-only view for non-assigned employees, auto-close cron job | Illegal transitions rejected; non-assigned employees cannot write or transition; full `ticket_events` and `activity_events` trail recorded. |
| **Phase 7** | Boss-employee private threads (with read-only colleague view), staff channel (`staff_announcements`) with employee acknowledgements (`acknowledge_staff_post`) | A third employee cannot post in someone else's thread; customers receive zero rows; acknowledgement counts and timestamps accurate. |
| **Phase 8** | Performance analytics: SQL views/functions, Boss analytics dashboard, date & employee filters, side-by-side comparison, activity timeline, CSV export, metric definitions panel | Hand-calculated fixture data matches dashboard calculations (Avg, Median, P90); employees see only their own numbers; CSV export writes to `audit_log`. |
| **Phase 9** | Stories (24-hour expiry enforced by RLS and cleanup cron job), customer announcements, in-app notification polish | Expired story vanishes immediately at expiry; customers cannot reply to or create announcements; employee flag checks enforced. |
| **Phase 10** | PWA manifest (`app/manifest.ts`), icons (`192`, `512`, `maskable`), install prompt, offline shell (`/offline`), Service Worker (`NetworkOnly` for authenticated routes), Web Push subscription & mock test | Manifest and service worker pass PWA checks; push subscription and notification dispatch tested with a mock. |
| **Phase 11** | Security review, load check at 60 accounts (1 boss, 4 employees, 55 customers), monitoring config, backup/restore runbook, production deploy config, `docs/FINAL-REPORT.md` | Full unit + E2E test suite passes; 60-account simulation passes; every item in `docs/security-checklist.md` verified and checked off. |
